# P3 Sim plan: Theoretical
#
# The bots do exactly this. Edit it, save, and start a P3: it's read again every start. Your own class's
# lines are what you do (they set when sections end); the other four are the bots'.
#
# Each class: where it starts, then its steps in order, one a line:   <section> <seconds into it>  <what>
#
#   T1 .. T5             that section's terminal (done at that time; the bot's there up to 2 s before, solving)
#   ll / rl              the section's left / right lever (or by name: east lever, west lever, high lever, low lever)
#   SS  Lights  Arrows  i4    a device (Lights, Arrows and i4 can be done in an earlier section)
#   gate                 blow the section's gate (from where it stands)
#   at <spot>            be standing on a spot by then
#   ee2 / ee3 / ee4 <spot>    the same, as that section's early enter (the party leaps onto it there)
#   leap <class>         Infinileap onto them (wherever they are; on the move: once they stop)
#   start <spot>         where it stands when P3 starts
#
# Section 5 is the core, open. Spots: any job's stand (T2, west lever...), i2, Lights, high EE3, EE3,
# core (the core front, EE4), recore, or "x y z".
#
# Between steps a bot moves the one fixed way (your recording in the Moves tab, else built in, else the
# recorded runs), leaving as late as it can, sped up only where these times are tighter than the move.
# A section that starts late (someone's slow) moves everything in it later; a leap onto you waits until
# you're on your spot.
